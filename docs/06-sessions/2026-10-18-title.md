# 2026-10-18: The title, native play from power-on, the resets, and Time Attack (WL3-055 to WL3-058)

The owner asked the agent to continue where the last session stopped:
WL3-055, tracing the title and porting its Continue path, then native
play from power-on.

## Outcomes

- The tracer records the title (`title` layout, hooked at
  `TitleStateTable.jump`, 01:4039): its variables, the temporary
  palettes, the progress, `wTransitionParam` to `wcef1`, and GFX RAM's
  menu objects. `title-continue-game-017`'s trace has 142 title loops.
- `wl3pc.extract.title` decodes the title's framesets, OAM tables,
  palettes, graphics, maps, and box (`title.json`).
- `TitleSim` translates the title with a save (sub-states 0-3, 7, 8) and
  `InitIntroSequence`'s intro branch. Its first step check found one
  difference, fixed: with a save the plane's Wario is set up but not
  animated until the start menu. `TitleVram` draws it.
- `InitIntroSequence` clears `wGlobalCounter`. The step check now keeps
  that loop and the next in one visit, and a run counts its untraced
  loops from the counter each loop leaves (`_run_untraced`), instead of
  from the count between two traced loops.
- Runs start at power-on when the movie does: the movie's battery save
  goes through the ported load (`SaveLoad`), and the title, the map, and
  the way into a level run natively with every RAM byte known, nothing
  seeded. The window does the same (`make run SAVE=…`,
  `LevelRunner.power_on`).
- `make continue-movie` takes scripted presses (`PRESSES=`, `TICKS=`); a
  second movie, `title-continue-level-game-017`, continues into level
  `$70`, plays, pauses, and goes to the map, which saves.
- WL3-055 is done; the title without a save and a level resumed from a
  save are WL3-056 ([the title](../02-research/title.md)).
- While the sweeps of that commit ran: a level resumed from a save
  (WL3-056). `game-016`'s cartridge RAM at its reset (from the save load's
  capture) is stored as a save; a movie from it
  (`title-continue-level-save-game-016`) takes Continue into level `$41`
  and climbs down, walks, and jumps. `LevelSim.resume_level_with_camera`
  translates `StartRoom_FromLevelStart`'s resume, with the level map from
  the SRAM the load left. The first recording was too static (Wario
  idling on a vine) and was recorded again with a climb down.
- Then the intro (WL3-056): `make continue-movie SAVE=none` records a
  power-on movie with no save (`title-new-game`: the intro, then New
  Game); the title's layout gains the three layers' scroll. `TitleSim`
  translates the intro's phases, the logo's drift, the layers' scroll, and
  `SlowFadeInScreen`; all of its loops matched the first time.
  `CgbScreen.render` takes a per-line scroll for the intro's mid-frame
  writes, and `TitleVram` steps the fade at the intro's end, which takes
  BG and OBJ palettes toward the title's (a first model faded the BG
  only; three screens told). A game state with no port (the language
  selection) is now named as not ported instead of run as a level.
- Then New Game's language selection (WL3-056): the title's layout has
  a twin hooked at `LanguageSelectionStateTable.jump` (01:483f), the title's
  extractor adds its font, palettes, text maps, frameset, and OAM table

  title's RAM). It matched the first time. `title-new-game` was recorded
  again, longer (down, up, and A at the language selection, then the
  map's prologue).
- The window's screenshots take exactly the ticks asked for (they could
  run a loop past), and from power-on they are compared with the
  original's frames by the trace's loops: the original has lag frames,
  so ticks drift.
- Then the game's resets (WL3-057, the owner asked to go on): four
  power-on movies from `game-017`'s save (`make continue-movie`):
  `title-demo-game-017` (the start menu left alone: two of Action Help's
  demos, each ending in `InitWithoutDemoPowerUpReset`),
  `title-clear-data-game-017` (Clear Data's Yes), `title-reset-map-game-017`

  a `LevelSim` made as at power-on, from the SRAM as it now is, whose state
  the running one takes. `hDemoPowerUp` became the `LevelSim`'s; the SRAM
  is kept whole (`loaded_sram`, `level_map_sram`, `current_sram`);
  `InitLevel` gives an extracted level the SRAM's bytes it never writes;
  `LevelRunner.frame` takes pressed from `wJoypadDown`, which `Init` clears.
  On the way: the first step check compared a reset's way out with a frame
  inside `Init` (WRAM half cleared): it now compares the title's first loop
  after it; the four-button loop runs no state, so no screen records it:
  the harness takes its joypad from the frames; and level visits keep a
  reset's title with the visit it left ([the resets](../02-research/resets.md)).
- Then Time Attack's description (WL3-058): no save has Time Attack (a
  perfect game sets it), so `oracle_save --invent-time-attack` stores an
  invented one, `game-017`'s save with `wGameModeFlags`' bit 1 set in both

- Then the pause menu's drawing (WL3-052): the extractor (format 3) adds
  `PauseMenuGfx`, the transformations' tiles, and the menu's maps;
  `SaveScreenVram` draws the menu (its counts, Time Attack's times) and
  the level's save screen; the step check draws visits from a level too;
  the window shows the menu instead of its stand-in. It matched the first
  time. A new movie that pauses and goes back to the level
  (`title-pause-return-game-017`) found two gaps in the checks, not the
  port: after `ExitPauseMenu` the original's virtual OAM is the level's
  sprites, which the port keeps as drawn objects (now not compared), and
  the run treated the menu's loops between two level updates as a fade,
  run with the last joypad (now `_run_level_gap` runs a screen's traced
  loops there as after a level).
- The owner then left, allowing the agent to go on to the next item:
  Action Help from the pause menu (WL3-051, WL3-052). `OpenActionHelp`
  from the menu, and `ReturnToPauseMenuFromActionHelp`, whose loop ends
  with the pause menu's `InitPauseMenu_SkipBackupVRAM` (the port runs it
