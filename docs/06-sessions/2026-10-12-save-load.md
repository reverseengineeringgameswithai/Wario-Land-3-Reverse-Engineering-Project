# 2026-10-12: The save's load (WL3-055, step 1)

While the faster sweeps ran, the agent took the next task, native play
from a save, and its first step.

## Outcomes

- A read-only subagent scoped WL3-055 from the disassembly; its key
  findings were checked against the source and written into the task: the
  save loads at power-on (`Init`, `ValidateSaveData`, `InitGameState`),
  the title only offers Continue, and `CalculateChecksumLong`'s loop is
  wrong in a way the port must keep.
- A second subagent translated `ValidateSaveData` and its routines
  (`SaveLoad`) in an ignored copy, with 13 unit tests; the pause menu's
  `SaveLevel` checksum now uses the same routines, unchanged in result.
- The agent wrote `wl3pc.oracle_save`: it replays each owner's movie to its
  end against the movie's 2,176 recorded memory checkpoints, keeps the save
  it leaves, and captures the load from each save, from none, and from
  `game-016`'s own reset; and a parity script comparing the port with each
  capture (`make save-load-check`). All 19 loads are equal, byte for byte
  ([the save's load](../02-research/save-load.md)).

- Step 2 in part: `make continue-movie` records a power-on movie from a
  stored save through the title's Continue (A at the start menu; Start
  does nothing there) to the map. With `game-017`'s save, its trace's 555
  map loops, from the map's start after the title (transition 0, never
  compared before), all match, with 17 VRAM snapshots and 16 screens.
